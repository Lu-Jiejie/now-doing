# now-doing

A tiny Windows tray agent that publishes what you are doing as a public JSON file your static blog can `fetch` directly — no server of your own: hosting and storage ride on Cloudflare and an R2 bucket.

- Single 1.8 MB exe, portable data directory next to it (never touches C:)
- Sits at **24 MB working set / 4 MB private bytes / 0 ms CPU over 20 s**, zero webview child processes
- Publishes nothing by default: only apps listed in `rules` are ever visible

```
Foreground window ──┐
Media session ──────┼─→ privacy pipeline (allowlist / alias / keywords) ─→ fingerprint ─→ R2 ─→ Cloudflare edge ─→ your blog
Idle time ──────────┘                                                        (write on change, heartbeat otherwise)
```

## 1. Quick start

```powershell
# run cargo from PowerShell (schannel fails under bash)
cd apps/desktop
$env:CARGO_PROFILE_DEV_DEBUG='0'; $env:CARGO_PROFILE_DEV_INCREMENTAL='false'
cargo test && cargo build --release

# build + test + copy into the deploy directory
pwsh -File ..\..\scripts\build.ps1 -OutDir 'D:\Software\now-doing'
```

The first run creates `data\` next to the exe: `config.json` (hand-written, the app only reads it), `device-id`, `seq`, and `now-doing.log` (rotates at 512 KB).

Two things worth knowing up front:

- Editing `config.json` **requires a restart**. There is no hot reload, on purpose.
- The exe must live in an **ordinary folder**. If the directory carries a `Low Mandatory Level` integrity label (sandboxes, some extractors, sync clients), the process inherits low integrity and Windows refuses the tray icon.

## 2. Configuration

Field names are **camelCase**. Every field has a default, missing fields fall back to it, unknown fields are ignored.

**Top level**

| Field | Default | Meaning |
|---|---|---|
| `version` | `1` | Config format version |
| `paused` | `false` | Pause reporting (the tray menu edits this too) |
| `autostart` | `false` | Mirror of the run-at-login switch, which really lives in `HKCU\...\Run` |
| `heartbeatSecs` | `90` | Heartbeat: with no change at all, still write this often. Readers use it to tell "away" from "offline". Clamped to 30–3600 |
| `minGapSecs` | `5` | Minimum gap between writes while the state keeps changing |
| `changeDebounceSecs` | `3` | A new state must persist this long to count as a change; switching away and back writes nothing |
| `proxy` | `""` | HTTP proxy, e.g. `http://127.0.0.1:7890` |
| `deviceName` | `""` | Published as `device.name`; **empty publishes `desktop`** — the hostname is never sent by default |
| `dryRun` | `false` | Collect only, never upload; writes `data\presence.json` so you can test rules |

**`sink` (where it writes)**

| Field | Default | Meaning |
|---|---|---|
| `kind` | `"r2"` | Only R2 is implemented |
| `endpoint` | `""` | `https://<account-id>.r2.cloudflarestorage.com` |
| `bucket` | `""` | Bucket name |
| `objectKey` | `"presence.json"` | Object name, and the path your cache rule matches |
| `publicUrl` | `""` | URL readers use, e.g. `https://presence.example.com/presence.json` |
| `accessKeyId` | `""` | Access Key ID of the R2 token (32 hex chars) |
| `secretAccessKey` | `""` | Matching secret (64 chars, shown once) |
| `purgeToken` | `""` | Optional Cloudflare API token holding `Cache Purge` |
| `zoneId` | `""` | Zone ID of your domain; with `purgeToken` set, the edge is purged after every write |

**`privacy` (what may be published)**

| Field | Default | Meaning |
|---|---|---|
| `unknownApp` | `"hide"` | Apps without a rule: `hide` publishes nothing, `generic` publishes `{app:"other"}` |
| `idleAfterSecs` | `120` | No input for this long flips the status to `idle`. Clamped to 30–86400 |
| `hideFocusWhenIdle` | `true` | Clear `focus` on idle so "what was open when you left" never leaks |
| `mediaBlockKeywords` | `[]` | Drop the whole track when title or artist contains any of these (fuse for private audio) |
| `rules` | `[]` | The allowlist |

**`rules[]`**

| Field | Required | Meaning |
|---|---|---|
| `matchProcess` | yes | Executable name, e.g. `Code.exe`; a trailing `*` matches a family. **Matched locally, never published** |
| `alias` | no | Published id replacing the derived one (`Code.exe` → `code`) |
| `category` | no | Free-form tag your blog can map to wording or an icon. **`media` is special**: only apps tagged `media` may publish a track |

```jsonc
{
  "heartbeatSecs": 60,
  "minGapSecs": 10,
  "changeDebounceSecs": 4,
  "sink": {
    "kind": "r2",
    "endpoint": "https://<account-id>.r2.cloudflarestorage.com",
    "bucket": "now-doing",
    "objectKey": "presence.json",
    "publicUrl": "https://presence.example.com/presence.json",
    "accessKeyId": "<32 hex chars>",
    "secretAccessKey": "<64 chars>"
  },
  "privacy": {
    "mediaBlockKeywords": ["meeting", "interview"],
    "rules": [
      { "matchProcess": "Code.exe", "alias": "code", "category": "dev" },
      { "matchProcess": "chrome.exe", "category": "browse" },
      { "matchProcess": "cloudmusic.exe", "category": "media" }
    ]
  }
}
```

## 3. Cloudflare setup

**3.1 Bucket + custom domain**: R2 → Create bucket → bucket Settings → Public access → Custom Domains → Connect Domain (the CNAME is added for you). The `r2.dev` hostname does not support caching, so a custom domain is mandatory.

**3.2 Cache rule**: Caching → Cache Rules → Create rule

- Expression, this and nothing else: `http.host eq "presence.example.com" and http.request.uri.path eq "/presence.json"`
- Cache eligibility `Eligible for cache`; Edge TTL `Ignore cache-control and use this TTL` = **10 s**; Browser TTL `Bypass cache`

> ⚠️ Never add `http.request.method eq "GET"` to that expression. Single-file purge internally uses a different method name, so matching on GET makes purge fail silently.

**3.3 CORS** (required for cross-origin reads): bucket → Settings → CORS Policy

```json
[{ "AllowedOrigins": ["https://example.com", "https://www.example.com"],
   "AllowedMethods": ["GET", "HEAD"], "MaxAgeSeconds": 86400 }]
```

`AllowedOrigins` takes `scheme://host[:port]` only — no path, no trailing slash. `https://*.example.com` does not match the bare domain, so list both.

**3.4 Two tokens, do not mix them up**

- **R2 write key (required)**: `https://dash.cloudflare.com/<account-id>/r2/api-tokens` → Create API Token → **Object Read & Write** → pick the bucket. That screen shows the Access Key ID (32 hex), the secret (64 chars, once) and the endpoint.
- **Purge token (optional)**: avatar → My Profile → API Tokens → use the **Cache Purge** template, or a custom token with **Zone → Cache Purge → Purge**. `zoneId` sits in the API block on the zone Overview page.

The write key cannot purge (401) and the purge token cannot write. Do not go to **Account API Tokens**: that page has neither S3 keys nor `Cache Purge`.

**3.5 Measured**: `PUT` into R2 385–430 ms steady state / read-after-write 288 ms / edge hit 210–280 ms / staleness without purge 7.8 s / write-then-purge about 1.9 s.

## 4. Data protocol

`GET https://presence.example.com/presence.json`

```ts
export interface Presence {
  /** Protocol version, currently 1 */
  schema: number
  device: { id: string; name: string; os: string }
  /** Monotonic; drop any response whose seq is lower than the one you hold */
  seq: number
  status: 'active' | 'idle' | 'paused'
  /** Unix seconds, and the same instant as RFC 3339 */
  ts: number
  updatedAt: string
  /** Heartbeat interval; a sensible offline threshold is max(60, 3×) */
  heartbeatS: number
  focus: Focus | null
  media: Media | null
}

export interface Focus {
  /** Public id: an alias, or derived from the executable. The real process name never appears */
  app: string
  category: string
  /** When the current app took focus, and for how many seconds */
  since: number
  seconds: number
}

export interface Media {
  /** Scrubbed: links dropped, paths reduced to a basename, truncated to 80 chars */
  title: string
  artist: string
  /** Public id of the player */
  app: string
}
```

`focus` / `media` being `null` means "nothing worth publishing", not "field missing". These three types are already exported by `@now-doing/presence-client`, so import them from the package instead of copying them.

Four deliberate omissions:

1. **No `offline` status.** A disconnected client cannot write anything, so offline has to be inferred from `ts`.
2. **No playback state, album or position.** The players people actually use on Windows (NetEase Cloud Music) leave those empty; reporting a frozen playhead costs writes and says nothing.
3. **No human-readable text.** `label` and friends are gone: wording and i18n belong to the blog, the protocol only carries ids.
4. **The track title is the only free text that ever leaves the machine**, so it needs an explicit per-app `category: "media"` opt-in. A browser having a rule does not mean you agreed to publish what it is playing.

## 5. Using it from a blog

With CORS in place a static page can `fetch` directly. **Do not fetch at build time** (SSG would bake that instant into the HTML) — fetch in `onMounted`.

```ts
// Minimal: work out offline yourself
import type { Presence } from '@now-doing/presence-client'

const res = await fetch(url, { cache: 'no-store' })   // let Cloudflare do the caching
const p: Presence = await res.json()
const age = Date.now() / 1000 - p.ts - skew           // skew from the first good response
const state = age > Math.max(60, p.heartbeatS * 3) ? 'offline' : p.status
```

```ts
// Or use the composable shipped here
import { usePresence } from '@now-doing/presence-client'

const { presence, staleness, error, refresh } = usePresence({
  url: 'https://presence.example.com/presence.json',
  interval: 15_000,      // 15 s is plenty: the edge is never fresher than 1–10 s
  pauseWhenHidden: true, // stop polling in a hidden tab, catch up on return
})
// staleness: 'live' | 'recent' | 'stale' | 'offline'
```

The package already handles the three easy mistakes: dropping out-of-order `seq`, **clock skew** (measured from the first response, so a laptop an hour fast will not declare you offline), and pausing on `document.hidden`. `examples/vue/PresenceCard.vue` plus `messages.ts` (zh/en phrase tables) are there to copy.

Suggested mapping: `offline` → not at the computer / `paused` → not sharing right now / `idle` → away (and `focus` is usually `null` too) / otherwise look up `focus.app`, fall back to `focus.category`, and add a second line "listening to <title> — <artist>" whenever `media != null`.

Gotchas: poll every 15 s; **never add `?t=<timestamp>` cache busters** (Cloudflare's cache key includes the query string, so that bypasses the edge on every request); send a plain `GET`/`HEAD` without custom headers, which would trigger a preflight.

## 6. Command line

```
now-doing                    resident (tray)
now-doing --watch            live preview: every change prints the status plus the exact presence.json body
now-doing --probe            one-shot: raw samples, what would be published, and the config status
now-doing --media            every media session the system knows, plus the caption fallback result
now-doing --seal             move the four credentials out of config.json into a DPAPI-encrypted secrets.bin
now-doing --purge            purge the edge once, to verify purgeToken / zoneId
now-doing --resolve <host>   compare the system resolver with the built-in fallback resolver
```

`--watch` and `--probe` read the foreground window title so you can write rules. The resident loop **never puts a title into `focus`**; the only exception is the caption fallback for players that register no media session (NetEase Cloud Music), which reads the window title of apps tagged `category: "media"` and extracts just the track and artist.

## 7. Known limitations

- **NetEase Cloud Music**: title and artist only — album, artwork and position are empty, and play/pause cannot be inferred from the caption.
- **Zombie sessions**: the page is closed but the process lingers, so Windows still reports it as playing. The agent drops a session when the same track sits at the same position for three polls; players without a timeline (NetEase) are exempt and therefore never caught.
- **A paused player keeps showing the last track**: the protocol carries no playback state, so only a track change updates anything.
- **UWP apps**: the foreground window belongs to `ApplicationFrameHost.exe`, the real app cannot be resolved, so they count as unknown.
- **Windows only**: the collection layer is Win32 / WinRT throughout.
